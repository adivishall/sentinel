# Security invariants

Each invariant is a property the code enforces structurally, with the tests that
would fail if it stopped holding. `tests/test_invariant_table.py` checks that every
test named here exists, so this table cannot silently drift from the suite.

| Id | Invariant | Enforced by | Tests |
|---|---|---|---|

| INV-PROV-2 | Invalid, revoked, expired, superseded or unverified facts cannot authorise a consequential action under any policy version | the registry floor `min_fact_provenance` in `capabilities.authorize`, which no policy can lower, on every consequential capability; the `block-failed-fact-provenance` / `review-unverified-facts` rules. | INV-DEPLOY-1 | An authoritative service is not reachable from the network without authentication unless explicitly started as an audited insecure demo | `sentinel/api/server.py` (`check_bind`, the Host check) | `tests/test_secure_deploy.py::test_a_network_bind_without_a_key_is_refused`, `tests/test_secure_deploy.py::test_r1_dns_rebinding_is_refused_by_the_host_check` |

Underneath these, `tests/test_invariants.py` pins the ten original
decision-integrity invariants (attacker text cannot change a trusted verdict,
model output cannot bypass capability policy, model content is never trusted
evidence, unknown claims fail safe, malformed input never yields an
irreversible action, high-value effects need authorization, audit tampering is
detectable, policy versions are explicit and replayable, evidence provenance is
preserved, one engine behind every surface), with property-based checks.

What these do **not** say: a signature proves who stated a fact, not that it
is true; a signed policy can be a bad policy; an anchored checkpoint is as
strong as the place the anchor is kept; the temporal invariant is a tested
property over synthetic worlds, not an event-sourced proof. See
[LIMITATIONS](LIMITATIONS.md).
